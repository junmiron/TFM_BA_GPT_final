# Feature 7 - Web version of the spec in a new tab

Status: implemented (2026-11-06).

## Problem
There is no way to view `functional_specification.html` (with the inline
Mermaid SVG) in the browser from the UI. Downloading it via the existing
endpoint forces a file download: `server/api.py:get_file` uses
`FileResponse(path, filename=...)` which sets `Content-Disposition: attachment`,
so opening the URL in a new tab downloads instead of rendering.

## Design
- New endpoint: `GET /api/view/{session_id}/{name}`
  - Same path-traversal guard as `/api/files`.
  - Allowed inline types: `.html`, `.md`, `.svg`, `.png` (PDF stays a
    download-only artifact).
  - Returns `FileResponse(path, media_type=...)` **without** a filename so the
    browser renders it inline.
- In the same centered header action row (Feature 6), a secondary link
  directly next to the PDF button:
  **"View web version"** opening
  `/api/view/<session>/functional_specification.html` in a new tab
  (`target="_blank" rel="noopener"`).
- Greyed out (disabled span) when the run has produced no HTML yet.
- The HTML is generated by our own pipeline (self-contained, inline SVG), so
  inline serving is safe; it is served from the session folder only.

## Files touched
- `server/api.py` - `/api/view` endpoint.
- `ui/src/lib/api.ts` - `viewUrl(sessionId, name)` helper.
- `ui/src/components/Header.tsx` - link.
- `tests/test_server_api.py` - inline html served with no attachment header;
  404 for missing file; rejection of path traversal attempts.

## Acceptance
- Clicking "View web version" opens the rendered spec (SVG diagram included)
  in a new browser tab.
